# BusBuddy

**Never miss your bus again.**

BusBuddy is a mobile-first school bus tracking platform. Students see where their bus is, how many minutes until it reaches their stop, and whether it's running late. Parents follow their verified students' buses. Transportation administrators manage routes, stops and buses and publish service alerts.

Built for the Congressional App Challenge. **The included district ("Maplewood Valley Unified") is fictional and every bus in the demo is simulated.** The app labels this throughout as **DEMO LIVE SIMULATION**. BusBuddy is not affiliated with any school district.

## Quick start (about 3 minutes)

Requirements: **Node.js 20.19+** (tested with 22 and 24) and npm. You don't need PostgreSQL, Docker or any accounts: a project-local PostgreSQL server is downloaded as an npm package.

```bash
cd busbuddy
npm install          # installs all workspaces and generates the Prisma client
npm run setup        # creates .env with random local secrets and prints the local admin login
npm run dev          # starts PostgreSQL, applies migrations, seeds demo data, runs API + web
```

Open **http://localhost:5173** and click **Explore Demo**. No sign-up is needed.

| Service | URL |
| --- | --- |
| Web app | http://localhost:5173 |
| API | http://localhost:4000/api/v1 (health: `/api/v1/health`) |

## What a judge can do in two minutes

1. On the landing page, click **Explore Demo**. A private, temporary demo-student session opens on the dashboard.
2. Watch **Bus 12** move along Route 1 toward Jordan's stop, with a live countdown, schedule status and confidence indicator.
3. Click any stop in the **Route timeline** or on the map. The arrival estimate updates for that stop.
4. Set a **2, 5 or 10 minute arrival reminder**. Reminders arrive in **Notifications** (and as browser notifications while the tab is open, if you allow them).
5. Open **Track a bus** to see all six buses: approaching, in transit, **delayed**, scheduled, **completed** and **out of service** (with a stale-location warning).
6. Try **Demo as a parent**: two verified students (one on the delayed bus) and one link that stays hidden until the school verifies it.
7. Sign in as the local administrator (printed by `npm run setup`) to manage routes, stops, buses and announcements, and to pause, speed up or reset the simulation.

## Features

- **Live tracking map** (Leaflet + OpenStreetMap): road-following route lines, stops, animated bus markers, legend, fit-route / center-on-bus / center-on-stop controls, and a tile-failure fallback.
- **Tracking engine**: a deterministic simulation that interpolates along real road geometry, and a provider interface ready for district GPS (pull adapter + authenticated push endpoint).
- **ETA engine**: uses distance along the route (not straight lines), blended speed and stop dwell time. It reports schedule adherence (early, on time or late), handles zero speed and stale data, and shows a documented confidence heuristic.
- **Arrival reminders and delay alerts**: generated by the server once per trip with stable event keys, so there are no duplicates or notification floods.
- **Roles**: student, parent and administrator, all authorized on the server. Parent access requires a student-issued code **and** administrator verification.
- **Administration**: CRUD for schools, routes (with ordered stops and schedules), stops (map picker), buses and announcements, plus parent-link verification, an activity log, simulation controls and simulated analytics.
- **Accessibility**: text route timeline, status shown as icon plus text (never color alone), keyboard navigation, reduced-motion support, light and dark themes.
- **PWA**: manifest, icons and an offline fallback page. API data is never cached.

## Commands

```bash
npm run dev            # everything (database, migrations, seed, API, web)
npm run typecheck      # strict TypeScript across all workspaces
npm run lint           # ESLint
npm test               # unit + integration + component tests (Vitest)
npm run test:e2e       # Playwright end-to-end (desktop + mobile)
npm run build          # production build of the web app
npm run db:seed -- --reset-simulation   # re-seed and restore buses to start positions
```
